# 스마트글래스 실행 체크리스트

작성일: 2026-05-14

## 1. 목적

이 문서는 아래 두 경우를 모두 빠르게 확인하기 위한 실행 체크리스트이다.

- 센서 담당자와 함께 실제 센서까지 연결해서 확인하는 경우
- 센서 담당자가 없어도 mock 경로로 스마트글래스 표시를 먼저 검증하는 경우

핵심 목표는 다음이다.

```text
Pi에서 나온 상태가
앱 또는 글래스 표시 경로로 들어가
실시간 운동 해석 화면으로 보이는지 확인
```

## 2. 공통 확인

먼저 아래를 공통으로 확인한다.

- 같은 네트워크에 연결되어 있는지 확인
- Pi에서 WebSocket 포트 `8765` 를 열 수 있는지 확인
- Pi에서 글래스 UI 포트 `8080` 을 열 수 있는지 확인
- 앱 기준 Pi 주소를 확인한다
- 기준 계약 문서는 [스마트글래스_실시간_표시_Pi_메시지_계약.md](/home/ssafy/바탕화면/New Folder/S14P31C203/app/docs/스마트글래스_실시간_표시_Pi_메시지_계약.md:1) 을 따른다

## 3. 경로 A: 실센서 연결 확인

### 3.1 연결 구조

```text
EMG 4개 + IMU 3개
-> ESP32
-> Raspberry Pi serial
-> pi_sensor_bridge.py
-> WebSocket / Glass UI / App
```

### 3.2 실행

Pi에서:

```bash
cd /home/ssafy/바탕화면/New\ Folder/S14P31C203
./device/raspberry-pi/real_smartglass_bridge /dev/ttyUSB0
```

포트가 다르면 `/dev/ttyACM0` 같은 값으로 바꾼다.

### 3.3 확인 포인트

- ESP32 serial 연결이 잡히는지
- `connection_status` 에서 `pi_connected`, `esp32_connected`, `glass_connected` 흐름이 맞는지
- 브리지 로그에 sensor frame 이 계속 들어오는지
- 캘리브레이션 시작 후 `calibration_status` 가 나오는지
- 운동 중 `workout_event` 가 발생하는지
- 휴식 시 `rest_started`, `rest_finished` 가 나오는지
- 종료 시 `workout_completed`, `session_result` 가 나오는지

### 3.4 성공 기준

- 스마트글래스 화면 또는 앱 수신 화면이 실시간으로 바뀐다
- 최소한 정상, 빠름, 불균형, 휴식 중 하나 이상이 구분되어 보인다

## 4. 경로 B: mock 경로 확인

### 4.1 연결 구조

```text
mock workout stream
-> mock_pi_sensor_bridge.py
-> WebSocket / Glass UI / App
```

### 4.2 실행

Pi에서:

```bash
cd /home/ssafy/바탕화면/New\ Folder/S14P31C203
./device/raspberry-pi/mock_smartglass_demo
```

속도나 강도를 바꾸려면:

```bash
./device/raspberry-pi/mock_smartglass_demo pushup 1.2 1.1
```

### 4.3 확인 포인트

- `connection_status` 가 먼저 나오는지
- auto plan/cali/start 흐름이 이어지는지
- `workout_event` 로 상태가 바뀌는지
- mock 상태에서도 스마트글래스 화면이 정상, 빠름, 불균형, 휴식, 종료로 바뀌는지

### 4.4 성공 기준

- 센서 담당자가 없어도 스마트글래스 표시 흐름을 끝까지 볼 수 있다
- 앱 쪽 `smartglass_display` 또는 Pi glass UI 에서 상태 변화가 명확하게 보인다

## 5. 앱 쪽 확인 포인트

Flutter 담당자가 있으면 아래를 본다.

- `smartglass_display` 화면 진입
- `Preview Mode` 와 `Live Snapshot Mode` 전환 확인
- `Live Demo 재생` 버튼으로 내부 mock path 검증
- 실제 Pi 메시지를 붙였을 때 `applyPiMessageEnvelope()` 경로로 화면이 바뀌는지 확인

핵심 포인트:

```text
Pi message map
-> applyPiMessageEnvelope()
-> SmartglassSessionSnapshot
-> SmartglassDisplayState
-> 화면
```

## 6. 오늘 오후 추천 순서

센서 담당자 작업 여부에 따라 이렇게 간다.

### 6.1 센서 담당자가 아직 작업 중인 경우

1. `mock_smartglass_demo` 실행
2. mock WebSocket / glass UI 확인
3. Flutter 담당자가 `smartglass_display` 확인
4. payload 필드 누락 여부 점검

### 6.2 센서 담당자가 준비된 경우

1. `real_smartglass_bridge` 실행
2. ESP32 serial 프레임 유입 확인
3. 캘리브레이션 상태 확인
4. 운동 동작 시 `workout_event` 발생 여부 확인
5. 앱/글래스 표시 확인

## 7. 문제 발생 시 우선 점검

- serial 포트가 올바른지
- `pyserial`, `websockets` 설치가 되어 있는지
- Pi IP 와 앱 연결 주소가 맞는지
- `workout_event.details` 에 스마트글래스용 필드가 충분히 채워졌는지
- 캘리브레이션 진행률 `progress` 가 들어오는지
- 중간 연결 시 snapshot 또는 최신 상태 복구가 가능한지
